## Done

### Phase 0 — Project setup
- Vite + TypeScript, ESLint + Prettier, Vitest. `npm run dev | build | preview | test | lint`.
- Installed `three`, `@pixiv/three-vrm`, `@mediapipe/tasks-vision` (pinned 1.0.1), `kalidokit`.
- `npm run fetch-models` copies the MediaPipe WASM and downloads `pose_landmarker_full.task` +

  can also be overridden in the URL (`?maxPeople=2&debug=1`).
- **Verified: zero network requests outside localhost** (automated headless-Chrome check).
  - Found and removed MediaPipe's hidden telemetry (POSTs to `odml.pa.googleapis.com` every 60 s).
    A build step strips it and fails the build if it returns.
  - Production pages carry a Content-Security-Policy that blocks any non-local connection.

### Phase 1 — See the skeleton
- `camera.ts`: picks the camera (prefers `cameraDeviceLabel`), requested resolution, plain-language
  messages for blocked / missing / busy / unplugged cameras, auto-retry every 3 s, reconnects after
  unplug, detects a frozen camera (no frames for 5 s). Verified by simulating an unplug.
- `pose.ts`: PoseLandmarker in VIDEO mode, GPU with automatic CPU fallback, `numPoses = maxPeople`,
  loaded from local files only. If tracking fails to load it retries every 5 s.
- Mirrored camera feed + skeleton overlay, portrait 9:16 stage by default (landscape via config).
- Debug panel (`D`): screen fps, tracking fps, inference time, model/GPU, camera, resolution,
  people, confidence, settings warnings, error log. Render loop is wrapped — errors go to the panel.
- Guest prompts: "STEP IN — BECOME A CHARACTER" when nobody's there, "Step into the light…" when
  tracking confidence is low; privacy line "Camera is used live only — nothing is recorded."
- Hotkeys so far: `D` debug, `C` next camera, `F` fullscreen, `S` camera picture on/off.
- **Benchmark page `/bench/`**: tests lite/full × 640×480/1280×720 for 20 s each while rendering a
  test VRM character, shows a table and a big **YES / MAYBE / NO** verdict, plus warnings if nobody
  stood in view or the camera was too dark.
- First original placeholder character (`public/characters/grid-runner/model.vrm`, ~8k triangles),
  generated by `npm run make-placeholders` — owned by Grid City, no licensing issues.
- HTTPS test hosting: GitHub Actions workflow (`.github/workflows/gridcity-mirror.yml`) builds,
  lints, tests and publishes to GitHub Pages.
- 24 unit tests (settings parsing, benchmark verdict, camera errors, screen mapping).

## Apolosign TV benchmark (run by V)

| Setting | Camera gave | Screen fps | Tracking fps | Camera fps | Pose ms | Person seen |
| --- | --- | --- | --- | --- | --- | --- |
| lite @ 640×480 | 640×480 | 13.4 | 13.3 | 15.1 | 69.1 | 100% |
| lite @ 1280×720 | 1280×720 | 11.5 | 11.5 | 29.8 | 79.5 | 100% |
| full @ 640×480 | 640×480 | 10.4 | 10.4 | 15.1 | 89.5 | 100% |
| full @ 1280×720 | 1280×720 | 10.0 | 10.0 | 29.8 | 91.7 | 100% |

**Verdict: NO.** The TV's chip needs 70–90 ms per pose (≈11–14 per second); the 3D drawing itself
was cheap. Target is 24+. Laptop + TV (Mode B) is the event setup.

- The camera works when plugged into the TV (open question 5: **yes**). It delivers 30 fps at
  1280×720 and 15 fps at 640×480 (a camera limit, not lighting — the "too little light" warning on
  that screen was wrong and has been fixed).
- Possible later experiment (Phase 4, optional): run tracking in a background thread on the TV so
  the character animates smoothly at 30 fps while the pose updates ~12×/s. Motion would lag a
  little (~0.1–0.15 s). Not planned unless V wants a cordless booth badly enough to try it.
